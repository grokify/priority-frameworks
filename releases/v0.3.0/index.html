    Release Notes v0.3.0

    This release makes cross-framework normalization more accurate and hardens the score-to-level and level-count APIs against silent failures.

    Highlights

    • More accurate cross-framework normalization: levels now spread evenly across the full range
    • Safer ScoreRange lookups with explicit errors for nil frameworks and unknown levels
    • LevelCounts.Valid() to guard against typo'd level IDs

    Breaking Changes

    Normalization now spans the full range

    Normalize(), CompareAcross(), and MapTo() previously computed a level's position as index / total, which biased the top buckets and collapsed the second level of an odd-count framework into Critical. They now use index / (total-1), so the endpoints pin cleanly (index 0 → Critical, last index → Low) and the middle levels distribute evenly.

    For the 5-level Severity framework:

    // Before v0.3.0                    // v0.3.0+
pf.Normalize(sev, "critical")       // Critical      → Critical (unchanged)
pf.Normalize(sev, "high")           // Critical      → High
pf.Normalize(sev, "medium")         // High          → Medium
pf.Normalize(sev, "low")            // Medium         → Low
pf.Normalize(sev, "informational")  // Low            → Low

    Four-level frameworks (MoSCoW, General) already mapped 1:1 and are unaffected. A single-level framework now maps to Critical.

    Action: If you persist normalized priorities or compare them across frameworks, re-check the results — odd-count frameworks (Severity, Priority, IETF) will bucket differently.

    New Features

    LevelCounts.Valid()

    Add() and Increment() create a map entry for any string, so a typo silently inflates Total() while Slice()/ActionableTotal() ignore it. Valid() lets you check first:

    counts := pf.NewLevelCounts(pf.Severity())
counts.Valid("critical") // true
counts.Valid("criticl")  // false — catch the typo before Add()

    Explicit ScoreRange errors

    ScoreRange.LevelFromScore() now returns sentinel errors instead of panicking or failing silently:

    level, err := sr.LevelFromScore(score)
switch {
case errors.Is(err, pf.ErrNilFramework):   // ScoreRange has no Framework set
case errors.Is(err, pf.ErrUnknownLevel):   // a matched range references a level not in the Framework
case errors.Is(err, pf.ErrScoreOutOfRange): // score outside Min/Max
}

    Fixes

    • ScoreRange.LevelFromScore() no longer panics when Framework is nil, and reports an unrecognized level ID as ErrUnknownLevel rather than returning a nil level with no error.
    • MapTo() returns a pointer to the destination slice element instead of a loop-local copy, matching Parse().
